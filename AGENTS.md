# AGENTS.md

Guidance for coding agents working in this repository — Claude Code, Cursor, Codex and anything else that reads `AGENTS.md`. This is the single source; `CLAUDE.md` only points here.

## What this repository is

Galaxio: a plugin marketplace whose plugins install into **Cursor**, **Claude Code** and **Codex** unchanged. A plugin is authored once, in one `plugin.meta.json` plus a `skills/` tree; the six agent-specific manifests are generated. The tooling in `scripts/` exists to keep that single-source promise enforceable.

`plugins/galaxio-gatling` is the first plugin, migrated from the standalone repository
`galax-io/galaxio-gatling-pro` (now deprecated and archived). The plugin is the container and
is named for its domain; its skills are named for their tasks, which is why the skill inside it
is still `galaxio-gatling-pro` until the split renames it.

## Commands

```bash
npm run sync
```

```bash
npm run check
```

```bash
npm test
```

`sync` regenerates the manifests, `check` runs the same generator in `--check` (verify-only) mode plus the portability, link and security checks — all of them, so one run reports every failure — `test` runs the suite against `tests/fixtures/`. All three use Node built-ins only and work on a clean clone with no `npm install`.

The prose gates need `npm install` first, and CI requires them:

```bash
npm run format:check && npm run lint:md && npm run spell
```

Single test by name:

```bash
node --test --test-name-pattern "semver comparison" tests/checks.test.mjs
```

Run any check against one fixture tree (this is how the suite drives them):

```bash
node scripts/check-portability.mjs --root tests/fixtures/invalid-frontmatter
```

Release gate, comparing against a base ref (CI passes `origin/$GITHUB_BASE_REF`):

```bash
npm run check:version-bump
```

What a merge would announce, without announcing anything (needs `gh`, reads only):

```bash
node scripts/release.mjs --dry-run
```

## Authored vs generated

Authored — edit these:

- `marketplace.meta.json` — marketplace identity
- `plugins/<name>/plugin.meta.json` — everything about one plugin
- `plugins/<name>/skills/<skill>/SKILL.md` and the plugin's own README/CHANGELOG/scripts

Generated by `npm run sync` — never hand-edit (marked `linguist-generated` in `.gitattributes`, ignored by Prettier):

- `.claude-plugin/marketplace.json`, `.cursor-plugin/marketplace.json`, `.agents/plugins/marketplace.json`
- `plugins/<name>/.claude-plugin/plugin.json`, `.cursor-plugin/plugin.json`, `.codex-plugin/plugin.json`

`npm run check` fails on any drift, byte-for-byte, including a file that is merely missing.

## Writing a skill body

`SKILL.md` loads on every activation; `references/` loads per task. The split is by invariance, not by read frequency: a fact that holds on every stack — detection, the dispatch index, the invariants — is body, however long that makes the body. A fact that varies by version, build tool, language or protocol is a reference even when dispatch sends every task to it, which is why `versions.md` is read on every task and is still a reference — what it holds is a per-line matrix, not an invariant.

- **One file per dispatch cell, and siblings are never read together.** An agent reads one language file and one build file, so the same fact stated in all three `build-gradle-*` files is load-bearing in each. Do not dedupe across siblings — that is the split working, not drift. Only duplication _across_ axes is removable, and a reference restating a `SKILL.md` invariant is the clearest case, since the body is already in context.
- **One file owns the line-to-coordinate matrix.** In `galaxio-gatling-pro` that is `references/versions.md`: which release of each artifact pairs with which Gatling line. A version where behaviour changed — an API that arrives, a tool that stops working — is not a coordinate and belongs to the file documenting that change. A coordinate written outside the matrix is how the skill goes stale, and is why the greenfield default names a line rather than a release.
- **A skill states facts, coordinates and consequences.** Explain something only where the explanation stops a concrete mistake. Nothing in a skill describes its own construction, its coverage, or which file owns what — that contract is this section, and prose about it inside the body is paid for on every activation and changes nothing the agent does.

## Architecture

**`scripts/sync-manifests.mjs`** is the only place the three agent dialects differ. `claudePlugin()`, `cursorPlugin()` and `codexPlugin()` each project the same authored meta into one dialect; `claudeMarketplace()`/`cursorMarketplace()`/`codexMarketplace()` do the same for the catalogs. Codex drops subagents and Cursor rules; Cursor alone carries `rules` and `variables`; Claude Code alone carries `userConfig`. New dialect knowledge belongs in these functions and nowhere else. `buildOutputs()` returns `null` before emitting anything if the reporter already failed — the emitters read fields only the schema guarantees, so emitting on invalid input turns a precise error into a `TypeError`.

**The four checks** are independent scripts sharing `scripts/lib/`:

- `check-portability.mjs` — every `SKILL.md` is installable in all three agents unmodified
- `check-links.mjs` — relative Markdown links and manifest component paths resolve, and every file bundled under a skill is reachable from its `SKILL.md`
- `check-security.mjs` — file-type allowlist, no machine-specific absolute paths, no literal credentials in `hooks.json`/`.mcp.json`/`mcp.json`
- `check-version-bump.mjs` — a touched plugin bumped `version` and landed a CHANGELOG entry

`check-links.mjs` runs both directions of one edge, which is why they share a file. Forward: a link whose target is missing. Backward: from each `SKILL.md`, the closure over links that stay inside the skill; anything bundled but outside it is unreachable and ships without ever being loaded. Following a link out of the skill would launder the rest of the repository into the reachable set, so the closure stops at the boundary. Reachability is transitive — a reference may point at another. This proves a file is loadable, not that `SKILL.md` still indexes it: a reference dropped from the dispatch table stays reachable through a sibling, and catching that needs a separate check. `agents/` is exempt, and the extensionless names come from `EXTENSIONLESS_NAMES` in `scripts/lib/util.mjs`, shared with `check-security.mjs` — one check blessing a file while its sibling makes it unshippable is exactly the drift a single list prevents. Gitignored junk is skipped.

The two directions have opposite failure modes, and the grammar in `scripts/lib/markdown.mjs` is shared, so this matters: a link the grammar misses is a skipped verification going forward and would be a false accusation going backward. Forward resolution therefore reads `stripNonProse` output, while reachability reads the raw source — a reference documented inside a fence is still discoverable, and both directions stay fail-open on anything the grammar cannot see. Because a miss is an accusation, the grammar is anchored on the `](` that opens a destination rather than on the whole `[text](dest)` form (`matchAll` is non-overlapping, so the outer match of a nested image-wrapping-a-link would swallow the inner path), it reads `src`/`href` out of raw HTML, and it offers both the literal and percent-decoded spelling of every destination.

**`scripts/release.mjs`** is the other half of `check-version-bump.mjs`: the gate makes every plugin change move `version` and land a CHANGELOG entry, and this publishes those. **The unit of release is the marketplace, not the plugin** — plugins version independently, but a tag per plugin turns one relicense into thirty releases and thirty pages to read, so a merge produces one `release-<date>` tag with a section per plugin that moved.

State is the previous release, read from the Releases API, and the plan is the diff between the versions it shipped and the versions on disk. Nothing is stored, so a rerun is a no-op and a failed run is retried by re-running the workflow. Two fail-closed guards, both because "nothing released yet" is the reading that re-announces the whole marketplace: a dead API throws, and so does a previous tag that does not resolve — the API is the source of truth precisely because a tag can exist with no release behind it, hand-pushed or inherited from a migrated repository. Notes are each plugin's changelog section verbatim, folded into a `<details>` block past `COMPACT_LINES` and cut where a block starts, so a wrapped bullet is never split from its marker. One missing section publishes nothing at all, since the plugins around it would bury the break. `workflow_dispatch` on main exists so a fixed release can be cut without an empty commit.

**`scripts/check-all.mjs`** is what `npm run check` runs. It spawns each check and reports all of their failures: an `&&` chain stops at the first non-zero exit, so forgetting `npm run sync` would hide a leaked credential in the same commit behind a manifest-drift error. Ordering there is presentation only.

**`scripts/lib/`** is dependency-free on purpose. `util.mjs` provides `resolveRoot()` (the `--root` override), `listPlugins()`, `walk()` and `Reporter`. Every script collects all problems into one `Reporter` and returns a single exit code, so one run reports everything at once rather than stopping at the first failure. `run()` wraps `main()` and turns a throw into exit 1.

**`scripts/lib/schema.mjs`** implements a deliberate subset of JSON Schema and **throws** on any keyword it does not implement. Adding a keyword to `schemas/*.json` without adding it to `SUPPORTED` is a hard error, not a silently unenforced constraint. Widening a schema means widening this file.

**Fail-closed guards.** `detectRepoLicense()` reports an unreadable or unrecognized `LICENSE` as an error rather than skipping the per-plugin license check — a relicense is exactly when the guard must not turn itself off. `check-portability.mjs` gates the `skills/` directory that exists on disk, not the one the manifest declares, because all three agents load `skills/<name>/SKILL.md` by convention and an undeclared directory ships anyway.

## Invariants the tooling enforces

- `plugin.meta.json` `name` equals the directory name, kebab-case; `license` equals the repository `LICENSE`
- Skill directory names are globally unique across all plugins, and each matches its frontmatter `name`
- SKILL.md frontmatter carries **only** `name` and `description`. Every agent-specific key (`allowed-tools`, `model`, `when_to_use`, `paths`, `metadata`, …) is rejected with the owning agent named; it belongs in a sidecar such as `agents/openai.yaml`
- `description` starts with a capital letter, is under 1024 chars, and all descriptions in one plugin total under 4000 — they sit in context at startup
- SKILL.md body is at most 500 lines; overflow goes to `references/`, `scripts/`, `assets/`, and every file it goes to must be reachable from `SKILL.md`
- `components.*` paths are relative, start with `./`, stay inside the plugin, and exist
- Only source files under `plugins/` — allowlisted text extensions plus png/svg/jpg. No binaries, no archives
- Every plugin change needs a semver bump strictly greater than the base branch plus a `plugins/<name>/CHANGELOG.md` entry. Without the bump, Claude Code keeps serving the previous release
- Marketplace names reserved by Anthropic are rejected — a marketplace using one silently stops loading
- The bump and its entry must name the same version. `check-version-bump.mjs` checks for a `## [<new version>]` section rather than for a touched CHANGELOG, because that section is what the release publishes — proving it exists on the pull request is what stops the release from failing on main, after the change is already public
- Landing on main publishes one `release-<date>` for the marketplace, with a section per plugin whose version moved. No plugin version moves, no release

## Adding a plugin

Create `plugins/<name>/plugin.meta.json` (see `tests/fixtures/valid/plugins/demo-plugin/plugin.meta.json` for a complete example), write skills under `plugins/<name>/skills/`, then:

```bash
npm run sync && npm run check && npm test
```

```bash
claude plugin validate ./plugins/<name> --strict
```

Then install in at least one agent and exercise the skill for real before opening a PR; state which agent in the PR. `CONTRIBUTING.md` has the per-agent install commands and the full checklist. `docs/plugins-vs-skills.md` is the reference for the primitives and the three dialects.

Secrets are never committed. Declare `cursor.variables` (Cursor) or `userConfig` (Claude Code) in `plugin.meta.json` and reference them as `${VAR}`.

## Tests

`tests/fixtures/` holds **deliberately broken** trees — malformed JSON, leaked credentials, non-portable frontmatter. They are inputs to the suite, not marketplace content, and the checks exclude them by path (not by directory name, so a plugin may still ship a directory called `tests`). Tests that mutate a tree copy it to a temp dir first via `copyFixture()`.

Assertions check the _message_, not just the exit code — an error must name the file and the fix. Preserve that when adding checks.

## Conventions

- Node 22+, ESM only (`"type": "module"`), `.mjs` for scripts
- Prettier: single quotes in `.mjs`, double in JSON, 100 columns; `.gitattributes` forces LF, since `sync --check` compares byte-for-byte
- New vocabulary in Markdown or code comments must be added to `cspell.json` or CI fails
- `plugins/`, `scripts/`, `schemas/`, `tests/`, `.github/` and `package.json` are CODEOWNERS-protected
